# ntun-ng

Single-binary Go rewrite of the legacy `tun2org` system. See
`../.docs_and_plans/work/todo/refactor-single-go-binary.md` for the full plan.

## Status

All planned phases (1-7) implemented.

- Phase 1 (mux + agent): tests green.
- Phase 2 (relay: SSH auth password/agent, direct+bastion, reconnect, JSON
  config): tests green (real SSH needs manual integration).
- Phase 3 (TUN + routes + gVisor netstack glue, non-GPL, full `ntun up`):
  awaits manual integration (needs CAP_NET_ADMIN + real SSH).
- Phase 4 (IPv6 end-to-end) + Phase 5 (native UDP over mux + DNS hijack):
  tests green.
- Phase 6 (interface watch + rebind, state file + `ntun down`, optional
  `dns_listen` server): tests green.
- Phase 7 (install.sh + bench.sh + benchmarks doc): implemented.

## Binaries

- `cmd/ntun` — local client. `up` brings the full stack up (TUN + routes +
  gVisor netstack + tunnel + reconnecting SSH relay + interface watch + state
  file + optional DNS server). `down` tears down from the state file.
  `config init|edit`, `version`.
- `cmd/ntun-agent` — lightweight remote agent: reads a framed mux stream from
  stdin, writes to stdout, dials TCP + UDP targets and pipes data/grams.
- `install.sh` — `build` (devcontainer): compiles static binaries into
  `dist/`. `install` (user PC, no Go needed): copies `dist/` binaries,
  optional setcap. `uninstall`.
- `bench.sh` + `docs/benchmarks.md` — iperf3 comparison vs legacy.

## Packages

- `internal/mux` — binary, length-prefixed connection multiplexer (replaces the
  gob `DataMessage` protocol + double SOCKS5 hop).
- `internal/agent` — remote agent: drives a `mux.Session` and dials targets.
- `internal/relay` — SSH transport: auth (password/agent), direct/bastion,
  optional `proxy_command` (OpenSSH ProxyCommand / `ssh -W host:port` jump),
  agent upload+cache, reconnect w/ backoff, live `Open` over a swapping session.
- `internal/config` — JSON config + defaults + validation.
- `internal/tun` — TUN device (wireguard/tun) + addr/linkup/mtu (netlink on
  Linux, ifconfig on macOS/arm64).
- `internal/route` — route add/del (netlink on Linux, `route` on macOS).
- `internal/netstack` — gVisor netstack glue (link endpoint from io.ReadWriter,
  stack with ipv4+ipv6+tcp+udp+icmp, tcp/udp forwarders). Clean reimpl on
  Apache-2.0 gVisor; no tun2socks (GPL) code vendored.
- `internal/tunnel` — bridges netstack TCP/UDP conns to `relay.Open` (mux).
- `internal/app` — orchestrates a full run: tun → routes → netstack → tunnel →
  relay, with graceful teardown + post_start/stop scripts.
- `internal/version` — build metadata.

## Wire protocol

See `internal/mux/frame.go` doc comment. Big-endian, fixed 5-byte header
(4 length + 1 type). Types: OPEN, OPEN_OK, DATA, CLOSE, ERR, PING, PONG,
UDP_OPEN, UDP_DATA (UDP types land in a later phase).

## Build / install

Binaries are precompiled in the devcontainer (Go 1.23+) and installed on
user PCs without Go:

```
# devcontainer: compile static binaries into ./dist (then commit dist/)
cd ntun-ng
./install.sh build

# user PC: install prebuilt dist/ binaries (no Go, no compiler)
./install.sh install

# user PC dev fallback: no dist/ + Go present → builds on the fly
```

Always build with `CGO_ENABLED=0` (both `build` and the fallback do this):
no dep needs cgo, and the resulting binaries are static (`ldd` → "not a
dynamic executable"). The agent is uploaded to and exec'd on remote hosts
whose glibc may be older than the build machine's (e.g. Ubuntu 20.04 ships
glibc 2.31); a dynamically linked agent fails there with
`version 'GLIBC_2.32' not found`.

Dev equivalent of the build step:

```
cd ntun-ng
go mod tidy          # fetch gvisor, wireguard, netlink, x/crypto, x/sys, x/term
go vet ./...
go test ./...
CGO_ENABLED=0 go build -o ntun ./cmd/ntun
CGO_ENABLED=0 go build -o ntun-agent ./cmd/ntun-agent
```

`go.mod` lists direct deps; `go.sum` is generated by `go mod tidy`. Build tags
keep darwin/amd64 unsupported (only linux + darwin/arm64).

## Manual integration (phase 3, your env, needs privileges)

```
# 1. config
ntun config init --config ~/.tun2org/config.json   # edit username/forward_server/password/mode/routes

# 2. build agent + client (CGO off → static, runs on old glibc hosts)
./install.sh build
# (dist/ntun + dist/ntun-agent; put both on $PATH, or set agent_path in config)

# 3. run (needs CAP_NET_ADMIN — use sudo or setcap)
sudo ./ntun up --config ~/.tun2org/config.json
```

### Reaching the SSH server through a jump host

If the box where `ntun-agent` runs is only reachable via a jump host (like an
OpenSSH `ProxyCommand`), set `proxy_command` in the config. `%h` and `%p` are
replaced with the SSH host and port:

```json
{
    "username": "root",
    "forward_server": "195.154.160.42",
    "forward_port": 60001,
    "mode": "direct",
    "proxy_command": "ssh -W %h:%p srr1-lb-prd-si01",
    "auth": "agent"
}
```

This is equivalent to `ssh -o 'ProxyCommand=ssh -W 195.154.160.42:60001
srr1-lb-prd-si01' root@195.154.160.42`. The command runs via `sh -c` and its
stdin/stdout become the SSH transport. Note `interface` pinning is not supported
with `proxy_command` (no socket of our own to bind).

The SSH handshake is bounded (default 20s) and the whole proxy process group is
killed on timeout/cancellation, so a wedged or unreachable jump host fails
fast and Ctrl+C always exits. If your jump host is slow to connect, add
`-o ConnectTimeout=N` to the command. To mirror an OpenSSH setup that uses
forwarding, add `-o ClearAllForwardings=yes`:

```json
"proxy_command": "ssh -o ClearAllForwardings=yes -o ConnectTimeout=10 -W %h:%p srr1-lb-prd-si01"
```

The child's stderr is forwarded to ntun's stderr, so `ssh -v` diagnostics from
the proxy are visible in the terminal.

Expect logs: `app: tun tun0 up`, `app: route ...`, `relay: session
established`, `app: tunnel up`. Then traffic to `routes` CIDRs should reach the
forward server's network. Ctrl-C tears down (routes removed, TUN closed,
post_stop_script run).

Known remaining limitations:

- No interface-change rebind yet (phase 6); if the default route changes,
  the SSH socket may go stale until the session drops + relay reconnects.
- No `ntun down` state file yet (phase 6) to clean up after a crash.
- Optional local DNS server (`dns_listen`) not yet implemented (only the
  transparent TUN-side hijack is).
- Phase 3 netstack glue has no unit test (needs gVisor + privileges);
  validated by manual integration. Phase 1/2/4/5 have unit tests.

## Design notes (vs legacy)

- No `encoding/gob` reflection → fixed binary framing.
- No 1024-byte read cap → 64KiB DATA frames (`MaxDataLen`).
- No localhost SOCKS5 hop and no `armon/go-socks5` → agent dials the target
  directly via `net.Dial`; target address travels in the OPEN frame.
- Bounded per-conn receive buffer (`recvCap=128`) with explicit `ERR overflow`
  → the session read loop never blocks on a slow consumer.
- Explicit OPEN_OK handshake surfaces dial failures to the local `Open` caller.
- PING/PONG keepalive with timeout → dead-session detection (replaces the
  legacy 30s keepalive message that never checked for a reply).
